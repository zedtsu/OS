## 3. Исходный код скрипта (`search_text.sh`)

Сценарий разработан в текстовом редакторе `nvim`. Ниже представлен полный исходный код файла `search_text.sh`:

```bash
#!/bin/bash

# 1. Проверка наличия обязательного аргумента
if [ -z "$1" ]; then
    echo "Ошибка: Не указана строка для поиска."
    echo "Использование: $0 \"строка_для_поиска\" [имя_выходного_файла]"
    exit 1
fi

# 2. Инициализация переменных
SEARCH_STRING="$1"
OUTPUT_FILE="${2:-result_list.txt}" # Использование result_list.txt, если $2 пуст

echo "Ищу строку: \"$SEARCH_STRING\"..."

# 3. Поиск файлов .txt, содержащих искомую строку, и запись путей в файл
find . -type f -name "*.txt" -exec grep -q "$SEARCH_STRING" {} \; -print > "$OUTPUT_FILE"

# 4. Анализ результатов поиска
if [ -s "$OUTPUT_FILE" ]; then
    echo "Поиск завершен. Список файлов сохранен в: $OUTPUT_FILE"
    echo "Найдено файлов: $(wc -l < "$OUTPUT_FILE")"
else
    echo "Строка \"$SEARCH_STRING\" не найдена ни в одном .txt файле."
    rm -f "$OUTPUT_FILE" # Удаляем пустой файл, чтобы не мусорить
fi
```

### Разбор логики работы скрипта:
* **Строка 2:** Оператор `[ -z "$1" ]` проверяет, пуста ли первая переменная (строка поиска). Если да, скрипт завершает работу с кодом ошибки `1`.
* **Строка 9:** Конструкция `${2:-result_list.txt}` реализует подстановку значения по умолчанию для выходного файла.
* **Строка 13:** Утилита `find` ищет только файлы (`-type f`) с расширением `*.txt`. Для каждого файла запускается `grep -q` (тихий режим). Если строка найдена, `find` выводит путь к файлу (`-print`), который перенаправляется (`>`) в лог-файл.
* **Строка 15:** Опция `[ -s "$OUTPUT_FILE" ]` проверяет, существует ли файл и имеет ли он ненулевой размер.
* **Строка 17:** Команда `wc -l < ...` подсчитывает количество строк (и, соответственно, файлов) в отчёте.

## 4. Реализация пакетного сценария Windows (search_text.bat)

В ходе работы алгоритм поиска был полностью адаптирован под интерпретатор командной строки Windows (CMD/Batch) с сохранением исходной логики ветвления.

### 4.1. Полный исходный код скрипта `search_text.bat`
Ниже представлена финальная версия пакетного файла, зафиксированная в текстовом редакторе Vim:

```batch
@echo off
chcp 1251 > nul

if "%~1"=="" (
    echo Error: expected query.
    exit /b 1
)

set "SEARCH_STRING=%~1"

if "%~2" == "" (
    set "OUTPUT_FILE=result_list.txt"
) else (
    set "OUTPUT_FILE=%~2"
)

echo Finding: "%SEARCH_STRING%"...

type nul > "%OUTPUT_FILE%"

for /R %%F in (*.txt) do (
    findstr /C:"%SEARCH_STRING%" "%%F" >nul 2>&1
    
    if not errorlevel 1 (
        echo %%F >> "%OUTPUT_FILE%"
    )
)

for %%I in ("%OUTPUT_FILE%") do (
    if %%~zI GTR 0 (
        echo Finding was finished. List files was saved i: %OUTPUT_FILE%
    ) else (
        echo String "%SEARCH_STRING%" not founded in any .txt file
        del "%OUTPUT_FILE%" >nul 2>&1
    )
)
```

### 4.2. Подробный технический разбор синтаксиса Batch:
1. **Управление окружением и кодировкой:**
   * `@echo off` отключает отображение самих исполняемых команд в консоли для чистоты вывода.
   * `chcp 1251 > nul` принудительно устанавливает кодировку скрипта (Windows-1251), скрывая технический вывод команды.
2. **Проверка входных аргументов:**
   * Конструкция `if "%~1"==""` проверяет отсутствие первого параметра (строки поиска). Символ `~` автоматически удаляет кавычки вокруг аргумента, защищая скрипт от синтаксических ошибок.
   * `exit /b 1` завершает работу текущего скрипта с кодом ошибки `1`, не закрывая при этом само окно терминала.
3. **Рекурсивный поиск файлов:**
   * Команда `type nul > "%OUTPUT_FILE%"` создаёт новый пустой файл или очищает существующий перед началом поиска.
   * Цикл `for /R %%F in (*.txt) do (...)` выполняет рекурсивный обход текущей директории и всех её подкаталогов в поисках файлов с расширением `*.txt`.
   * Внутри цикла утилита `findstr /C:"..."` ищет точное совпадение строки. Перенаправление `>nul 2>&1` полностью глушит стандартный вывод и поток ошибок утилиты.
   * Проверка `if not errorlevel 1` проверяет код возврата предыдущей команды (`findstr`). Код `0` означает, что строка внутри файла найдена, после чего абсолютный путь к файлу (`%%F`) дописывается в итоговый лог (`>>`).
4. **Проверка размера итогового файла:**
   * Второй цикл `for %%I in ("%OUTPUT_FILE%") do (...)` используется для получения свойств созданного файла отчёта.
   * Модификатор `%%~zI` возвращает физический размер файла в байтах. Если размер больше нуля (`GTR 0`), выводится сообщение об успешном завершении работы. В противном случае выводится уведомление о том, что совпадений нет, а пустой файл удаляется с помощью `del`.
