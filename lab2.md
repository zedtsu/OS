## 1. Цель работы
Изучение процесса компиляции программ на языке C, генерации ассемблерного кода с использованием различных уровней оптимизации компилятора `gcc`, а также сравнительный анализ изменения размеров выходных текстовых файлов ассемблера (`.s`).

## 2. Постановка задачи
1. Создать рабочую директорию `~/lab1` и реализовать программу на языке C для нахождения корня нелинейного уравнения $x^3 - x - 2 = 0$ методом бисекции (деления отрезка пополам).
2. Задать входные параметры: отрезок $[1.0, 2.0]$, целевая точность вычислений $\epsilon = 10^{-6}$.
3. Выполнить компиляцию и запуск программы для проверки корректности математических расчетов.
4. Сгенерировать ассемблерные файлы с использованием флагов сборки `-g`, `-O0`, `-O1`, `-O2`, `-O3`.
5. Сравнить физический размер полученных ассемблерных листингов и сделать выводы.

### 6.2. Анализ ошибки сборки (Диагностика)
При первой попытке выполнить команду `make` компилятор GCC выдал ошибку:
```text
gcc -Wall -Wextra -O2 -c -o main.o main.c
gcc -Wall -Wextra -O2 -c -o math_func.o math_func.c
gcc -Wall -Wextra -O2 -o bisection main.o math_func.o -lm
make: *** Нет правила для сборки цели «parallel.o», требуемой для «bisection_parallel». Останов.
```
**Причина ошибки:** В файле `Makefile` была описана цель `bisection_parallel`, зависящая от объектного файла `parallel.o`. Однако само правило для компиляции `parallel.c` в `parallel.o` отсутствовало или содержало синтаксическую ошибку, а сам файл `parallel.c` ещё не был полностью готов.

## 7. Многопоточная реализация метода бисекции

Для ускорения расчетов отрезок поиска корней разделяется между несколькими независимыми вычислительными потоками. Исходный код логики многопоточности пишется в файле `parallel.c`.

### 7.1. Разбор фрагмента кода `parallel.c`
Согласно созданной структуре, в функции `main()` параллельного модуля выполняются следующие ключевые шаги:

1. **Инициализация параметров:** 
   Задается количество рабочих потоков (`num_threads = 4`), массивы дескрипторов потоков `pthread_t` и структур данных `ThreadData` для передачи индивидуальных аргументов в каждый поток.
2. **Логирование:** 
   Файл `results.txt` очищается, и в него записываются базовые параметры уравнения и исследуемый отрезок $[1.0, 2.0]$.
3. **Геометрическая декомпозиция (Разделение задачи):**
   Общий отрезок делися на равные части в зависимости от числа потоков:
   $$\text{segment\_len} = \frac{\text{total\_b} - \text{total\_a}}{\text{num\_threads}}$$
4. **Создание потоков:**
   В цикле рассчитываются индивидуальные границы отрезков $[a, b]$ для каждого ядра, прописывается ID потока, после чего вызывается функция динамического порождения потока:
   ```c
   pthread_create(&threads[i], NULL, find_root, &thread_data[i]);
   ```

## 10. Реализация вычислительного модуля (math_func.c)

Для обеспечения модульности проекта математические вычисления вынесены в отдельный файл `math_func.c`. 

### 10.1. Исходный код модуля `math_func.c`
Код содержит реализацию исследуемой математической функции и классического последовательного алгоритма деления отрезка пополам:

```c
#include "math_func.h"
#include <stdio.h>
#include <math.h>

// Реализация целевой функции f(x) = x^3 - x - 2
double f(double x) {
    return x * x * x - x - 2;
}

// Реализация последовательного метода бисекции
double bisection(double a, double b, double eps, int* iterations) {
    double c;
    int iter = 0;

    // Критерий корректности знаков на границах отрезка
    if (f(a) * f(b) >= 0) {
        printf("Ошибка: f(a) и f(b) должны иметь разные знаки\n");
        return 0;
    }

    // Основной цикл деления отрезка пополам
    while ((b - a) / 2 > eps) {
        c = (a + b) / 2;
        iter++;

        if (f(c) == 0) {
            *iterations = iter;
            return c;
        } else if (f(a) * f(c) < 0) {
            b = c; // Корень в левой половине
        } else {
            a = c; // Корень в правой половине
        }
    }

    *iterations = iter;
    return (a + b) / 2;
}
```

### 10.2. Особенности реализации алгоритма
1. **Проверка условий:** Строки 13–16 реализуют обязательную проверку теоремы Больцано-Коши. Если на краях отрезка функция имеет одинаковые знаки, корень методом бисекции гарантированно найти нельзя.
2. **Передача указателя:** Параметр `int* iterations` используется для возврата количества итераций в вызывающую функцию (поскольку сама функция возвращает вещественное значение корня `double`).
3. **Критерий останова:** Цикл продолжается, пока длина текущего полуинтервала превышает заданную точность `eps`.

## 11. Интерфейс модуля и главная точка входа

Для сборки многомодульного приложения были созданы заголовочный файл интерфейса и основной управляющий файл программы.

### 11.1. Заголовочный файл `math_func.h`
Для предотвращения повторного включения заголовочного файла использована стандартная директива препроцессора (Include Guard):

```c
#ifndef MATH_FUNC_H
#define MATH_FUNC_H

double f(double x);
double bisection(double a, double b, double eps, int* iterations);

#endif
```

### 11.2. Основной модуль программы `main.c`
Файл `main.c` связывает интерфейс вычислительного модуля с логикой взаимодействия с пользователем. В нём задаются начальные условия и вызывается функция расчёта:

```c
#include <stdio.h>
#include "math_func.h"

int main() {
    double a = 1.0, b = 2.0;
    double eps = 1e-6;
    int iterations;
    double root;

    printf("Решение уравнения x^3 - x - 2 = 0\n");
    printf("Отрезок: [%.1f, %.1f], точность: %.0e\n\n", a, b, eps);

    // Вызов функции последовательного метода бисекции
    root = bisection(a, b, eps, &iterations);

    printf("Корень: %.8f\n", root);
    printf("Количество итераций: %d\n", iterations);
    printf("Проверка f(корень) = %.2e\n", f(root));

    return 0;
}
```
